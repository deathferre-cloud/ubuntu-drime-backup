# Ubuntu Drime Backup

Постоянное одностороннее резервное копирование каталогов Ubuntu в **Drime** с сохранением путей от корня, журналом SQLite и небольшой веб-панелью.

[English](README.en.md) · [Устройство и эксплуатация](docs/OPERATIONS.ru.md) · [Восстановление](docs/RESTORE.ru.md) · [Изменения](CHANGELOG.md)

**v0.1.0 — предварительный выпуск.** Проект выделен из работающей установки на Ubuntu 22.04. Первичная полная копия исходной установки ещё выполнялась при подготовке выпуска. Проверки отдельных файлов и локального восстановления не заменяют проверку полного восстановления вашего сервера. Это независимый проект на основе rclone, без связи с командой Drime.

## Что умеет

- Копирует выбранные корни, например `/var/www`, `/home`, `/etc`, `/usr/local`, `/opt` и cron, в одно выделенное пространство Drime.
- Сохраняет пути: `/etc/nginx/nginx.conf` → `Drime:/etc/nginx/nginx.conf`.
- Повторяет отправку изменений и **не распространяет удаления** с исходного сервера.
- Сохраняет заменённые объекты отдельно от актуальных файлов и пишет метаданные Linux для восстановления.
- Подтверждает завершённые отправки по одному в SQLite. Частичный сбой не отменяет успех всей пачки.
- Повторяет проблемные объекты с задержкой и приоритетом, ограничивает зависшие команды.
- Использует дневной/ночной профиль и постоянный ручной стоп.
- Показывает в веб-панели очередь, проценты, ориентировочное время завершения и 10 последних ошибок с пояснениями на русском.
- Включает патчи rclone для экономии запросов к API и обработки конфликта создания папок Drime.

Это файловая копия работающей системы, **не атомарный снимок диска**. Дампы БД нужно создавать отдельно и складывать в один из выбранных каталогов. Сокеты и устройства имеют только записи метаданных. Символические ссылки передаются как текст назначения и восстанавливаются отдельной утилитой.

## Требования

- Ubuntu 22.04/24.04, x86_64, systemd, Python 3.10+.
- Выделенное пространство Drime и API access token с доступом к нему.
- Для сборки: `curl`, `ca-certificates`, `tar`, `python3`, GCC. Сборка скачивает закреплённые версии Go и rclone, проверяет SHA-256 и удаляет временный каталог.
- Для панели: существующий HTTPS-сайт, nginx и PHP-FPM. Для проверок: PHP CLI и OpenSSL.

В облачные пути должен писать только этот экземпляр службы. Несколько клиентов, одновременно изменяющих те же пути, не поддерживаются оптимизацией `fast_list_upload`.

## Установка

```bash
git clone https://github.com/deathferre-cloud/ubuntu-drime-backup.git
cd ubuntu-drime-backup
sudo apt-get update
sudo apt-get install -y python3 curl ca-certificates build-essential openssl php-cli
bash scripts/build-rclone.sh
bash scripts/check.sh
sudo bash scripts/install.sh --rclone ./dist/rclone-fast
sudo python3 scripts/configure.py
```

Сборка использует rclone **v1.75.1**, Go **1.27.2** и локальные патчи. Установщик не запускает копирование. Конфигуратор спрашивает workspace ID, email аккаунта, скрытый API-токен и выбранные каталоги. Секреты сохраняются только на сервере с правами `0600`; повторный запуск конфигуратора не перезаписывает готовую конфигурацию.

Проверьте `/etc/ubuntu-drime-backup/backup.json`. Пример в репозитории содержит workspace `0` и не предназначен для прямого запуска. Все выбранные корни считаются обязательными: их исчезновение вызывает ошибку, а не успешную пустую копию.

### Оповещения Drime и первый запуск

В этой версии проверяются правила `ransomware_suspected` и `malware_shared_by_team_member`: они должны быть включены вместе с email-уведомлениями. Обычные программные расширения из `cloud_guard_ordinary_extensions` не должны вызывать оповещение только из-за расширения. Проверьте реальные условия правил в своём пространстве; программа сама их не меняет. Это условие резервирования кода, а не заключение о безопасности содержимого файлов.

```bash
sudo python3 - <<'PY'
import json,sys
sys.path.insert(0,'/opt/ubuntu-drime-backup')
from safety import SafetyGuard
cfg=json.load(open('/etc/ubuntu-drime-backup/backup.json'))
guard=SafetyGuard(cfg)
guard.validate_policies()
guard.poll(force=True)
print('Drime workspace and alert observation are available')
PY
sudo systemctl enable --now ubuntu-drime-backup
sudo journalctl -u ubuntu-drime-backup -f
```

Проверка API выполняется без загрузки рабочих файлов. Технические параметры API Drime могут изменяться; сбой проверки требует разбора перед началом работы.

## Управление

```bash
# Статус и очередь
sudo systemctl status ubuntu-drime-backup --no-pager
sudo python3 -m json.tool /var/lib/ubuntu-drime-backup/status.json

# Постоянная ручная блокировка, сохраняется после перезагрузки
sudo python3 /opt/ubuntu-drime-backup/control.py stop

# После разбора причины: остановить, снять блокировку и запустить
sudo systemctl stop ubuntu-drime-backup
sudo python3 /opt/ubuntu-drime-backup/safety.py reset \
  --config /etc/ubuntu-drime-backup/backup.json \
  --reason 'Причина проверена и устранена; разрешаю повторный запуск'
sudo systemctl start ubuntu-drime-backup
```

`active` означает работающий процесс. Первая полная копия готова только после заполнения `initial_copy_complete`; текущие ошибки и новые изменения проверяются отдельно. История не очищается автоматически.

## Веб-панель

```bash
sudo python3 scripts/configure-panel.py \
  --public-url https://backup.example.com/backup-control.php
sudo systemctl enable --now ubuntu-drime-backup-control
```

Добавьте `config/nginx-panel.conf.example` в существующий HTTPS server block, укажите установленный PHP-FPM socket, проверьте `sudo nginx -t` и примените конфигурацию nginx. Личная ссылка находится в `/var/lib/ubuntu-drime-backup/control-url.txt`. PHP обращается к отдельной службе через Unix-сокет; произвольные команды и sudo из PHP отсутствуют.

Ссылка является ключом доступа. После входа ключ убирается из адреса, используются защищённая сессия, CSRF и POST для команд. В конфигурации nginx исключено журналирование этой ссылки; если перед nginx есть прокси, его журналирование настраивается отдельно.

Счётчики отображаются, например, так:

```text
Подтверждено файлов  020 464 (4,94%)
Осталось файлов     393 733
Передано байт       003 401 288 518 (0,59%)
Общий объём байт    578 445 093 029
```

Это иллюстрация формата, не текущие показатели конкретного сервера. Прогноз использует до 30 минут наблюдений; если размеры обработанных и оставшихся файлов несопоставимы, показывается ограниченный ориентир по количеству объектов.

## Профиль по умолчанию

| Период, Europe/Moscow | Передача | Ошибки |
|---|---|---|
| 07:00–19:00 | 4 потока, 8 запросов/с, 16 МиБ/с; после ошибки 2 потока / 4 запроса/с | 5 накопленных ошибок → постоянная блокировка; критический сбой → сразу |
| 19:00–07:00 | 7 потоков для мелких / 6 для крупных файлов, 24 запроса/с, без лимита полосы | Запись и повторы без автоматической постоянной блокировки |

Часовой пояс и границы дня в v0.1.0 закреплены в коде и unit. Ночная политика намеренно допускает продолжение после ошибок. Ручная и ранее сработавшая дневная блокировки сохраняются круглосуточно. Успех, полночь и перезапуск не сбрасывают дневной счётчик. Локальные ошибки видны в журнале и панели; письма отправляет только Drime по своим правилам.

## Проверки и лицензия

`scripts/check.sh` запускает тесты защиты, контроллера, прогноза, приоритетов очереди и HTTP-сбоев, локальную интеграцию rclone и PHP lint. Эти проверки не отправляют данные в Drime: имитатор API использует loopback, временный сертификат и тестовый токен. Проверки патчей Go, включая race detector, выполняются при сборке. CI запускает тот же процесс на Ubuntu 24.04 и проверяет чистую установку, права конфигурации и авторизацию Unix-сокета панели. Локальная интеграция также проверяет восстановление файлов, прав, UID/GID, времени изменения и ссылок.
